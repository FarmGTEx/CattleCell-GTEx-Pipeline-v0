# CattleCell-GTEx Single-Cell Pipeline: Test Dataset

This directory provides a small example dataset for testing the CattleCell-GTEx single-cell RNA-seq Nextflow pipeline.

The test dataset is intended to verify that the Nextflow workflow, Docker environments, reference files, Cell Ranger processing, and downstream Seurat analysis are configured correctly. Because the test dataset is intentionally small, the resulting cell numbers, clusters, marker genes, and other downstream results should **not** be used for biological interpretation.

## Test directory structure

The test directory contains the example FASTQ files and a sample information table:

```text
test/
├── README.md
├── samples.csv
└── data/
    └── fastqs/
        └── ...
```

The test currently contains three example sample IDs:

```text
MockA
MockB
MockC
```

## 1. Requirements

Before running the test, please make sure that the following requirements are satisfied:

- Java 17 or later
- Nextflow 25.04.2
- Docker
- `scrna_pipeline_env:latest`
- `local_seurat_env:latest`
- Reference genome FASTA
- Corresponding GTF annotation

Check Java and Nextflow using:

```bash
java -version
nextflow -version
```

Check that Docker is running and accessible:

```bash
docker ps
```

The pipeline uses two Docker environments:

```text
scrna_pipeline_env:latest
```

for Cell Ranger alignment and gene counting, and

```text
local_seurat_env:latest
```

for Seurat quality control, doublet detection, integration, clustering, and downstream analyses.

Please make sure that these Docker images are available and correctly configured before running the test.

## 2. Prepare the test samplesheet

The test samplesheet is located at:

```text
test/samples.csv
```

and contains two columns:

```text
sampleid,fastq_dir
```

For example:

```text
sampleid,fastq_dir
MockA,/path/to/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
MockB,/path/to/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
MockC,/path/to/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
```

### Important

The `fastq_dir` values currently provided in `samples.csv` are absolute paths from the development environment and must be changed to the location of the test FASTQ directory on your own system.

After cloning the repository, navigate to the Nextflow directory:

```bash
cd "CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow"
```

The absolute path of the test FASTQ directory can be obtained using:

```bash
realpath test/data/fastqs
```

For example, if this returns:

```text
/home/user/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
```

then `test/samples.csv` should contain:

```text
sampleid,fastq_dir
MockA,/home/user/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
MockB,/home/user/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
MockC,/home/user/CattleCell-GTEx-Pipeline-v0/1.Single-cell processing/Nextflow/test/data/fastqs
```

Each sample ID must match the corresponding sample naming used in the FASTQ files.

## 3. Prepare the reference genome

The pipeline requires a reference genome FASTA file and the corresponding GTF annotation.

For the CattleCell-GTEx analysis, the cattle reference genome and corresponding gene annotation should be used.

Store the reference files in a convenient directory, for example:

```text
reference/
├── reference_genome.fa
└── genes.gtf
```

The paths to these files are provided to Nextflow using:

```text
--ref_fa
--ref_gtf
```

The Cell Ranger reference generated from these files will be stored under:

```text
00_Reference/
```

If a compatible Cell Ranger reference has already been generated by a previous run, Nextflow can reuse the existing output when `-resume` is used.

## 4. Run the test

From the main Nextflow directory, run:

```bash
./nextflow run main.nf \
    -profile docker \
    --samplesheet test/samples.csv \
    --ref_fa "/absolute/path/to/reference_genome.fa" \
    --ref_gtf "/absolute/path/to/genes.gtf" \
    --species_name "Bos_taurus" \
    --mito_threshold 10 \
    --pcs_use 30 \
    --outdir test/results \
    -resume
```

Alternatively, if Nextflow is installed globally, use:

```bash
nextflow run main.nf \
    -profile docker \
    --samplesheet test/samples.csv \
    --ref_fa "/absolute/path/to/reference_genome.fa" \
    --ref_gtf "/absolute/path/to/genes.gtf" \
    --species_name "Bos_taurus" \
    --mito_threshold 10 \
    --pcs_use 30 \
    --outdir test/results \
    -resume
```

Replace:

```text
/absolute/path/to/reference_genome.fa
/absolute/path/to/genes.gtf
```

with the actual locations of the reference files on your system.

## 5. Main parameters

The parameters used in the test command are:

| Parameter | Description |
| --- | --- |
| `--samplesheet` | Sample information table used by the test |
| `--ref_fa` | Reference genome FASTA |
| `--ref_gtf` | Corresponding GTF annotation |
| `--species_name` | Species name used when generating the Cell Ranger reference |
| `--mito_threshold` | Maximum mitochondrial read percentage used during QC |
| `--pcs_use` | Number of principal components used for downstream dimensionality reduction |
| `--outdir` | Output directory |
| `-profile docker` | Run pipeline processes using Docker |
| `-resume` | Reuse successfully completed processes from previous executions |

For this example, we use:

```text
--mito_threshold 10
--pcs_use 30
```

which correspond to the default parameters used by the pipeline.

## 6. Expected workflow

A successful test run executes the major stages of the single-cell workflow:

```text
Test FASTQ files
      │
      ▼
Cell Ranger reference preparation
      │
      ▼
Cell Ranger count
      │
      ▼
Per-sample Seurat QC
      │
      ├── cell filtering
      ├── mitochondrial-content filtering
      └── doublet detection
      │
      ▼
Multi-sample integration
      │
      ├── normalization
      ├── dimensionality reduction
      ├── Harmony/integration
      ├── clustering
      └── UMAP
      │
      ▼
Test results
```

The purpose of the test is to verify successful execution of these workflow components rather than to reproduce the biological results of the complete CattleCell-GTEx dataset.

## 7. Expected output

With:

```text
--outdir test/results
```

the main output directories will be generated under:

```text
test/results/
```

and include outputs corresponding to:

```text
00_Reference/
01_Cellranger_Counts/
02_Seurat_QC/
03_Seurat_Integration/
pipeline_info/
```

### `00_Reference/`

Contains the Cell Ranger reference generated from the supplied FASTA and GTF files.

### `01_Cellranger_Counts/`

Contains Cell Ranger alignment and gene-counting outputs for the test samples.

### `02_Seurat_QC/`

Contains per-sample quality-control results and Seurat objects after filtering and doublet detection.

### `03_Seurat_Integration/`

Contains the integrated Seurat object, dimensionality-reduction results, clustering results, UMAP outputs, and other downstream analysis files.

### `pipeline_info/`

Contains Nextflow execution information, including reports, trace files, timelines, and workflow logs where enabled.

A temporary Nextflow:

```text
work/
```

directory will also be generated. This directory contains intermediate files and can require substantially more disk space than the final output.

After successful completion of the test and verification of the final results, the `work/` directory can be removed if intermediate files are no longer required.

## 8. Interpreting the test results

The test dataset is intentionally small and is provided only for workflow validation.

Therefore:

- cell numbers may be substantially smaller than in a real experiment;
- some cell clusters may contain very few cells;
- marker-gene results may not be biologically meaningful;
- UMAP structure may differ substantially from full datasets;
- doublet detection may behave differently from large datasets;
- some figures or downstream statistics may be sparse.

Successful completion of the workflow, rather than the biological interpretation of the resulting clusters, should be used to determine whether the test has passed.

## 9. Restarting an interrupted test

If the workflow is interrupted after some processes have completed, rerun the same command with:

```text
-resume
```

For example:

```bash
nextflow run main.nf \
    -profile docker \
    --samplesheet test/samples.csv \
    --ref_fa "/absolute/path/to/reference_genome.fa" \
    --ref_gtf "/absolute/path/to/genes.gtf" \
    --species_name "Bos_taurus" \
    --mito_threshold 10 \
    --pcs_use 30 \
    --outdir test/results \
    -resume
```

Nextflow will reuse successfully completed processes whenever possible.

## 10. Troubleshooting

### FASTQ files are not detected

Check that:

1. `fastq_dir` in `test/samples.csv` is an **absolute path**;
2. the directory exists;
3. the sample IDs in `samples.csv` correspond to the FASTQ naming;
4. the FASTQ files are readable by the current user.

For example:

```bash
ls -lh test/data/fastqs
```

### Docker error

Confirm that Docker is running:

```bash
docker ps
```

and that the required pipeline images are available.

### Blank figures

If the workflow completes successfully but some figures are blank, first check whether the Seurat RDS files were successfully generated under:

```text
03_Seurat_Integration/
```

The pipeline preserves the core Seurat objects even when individual visualization steps fail.

### Insufficient memory or CPUs

Process-specific CPU and memory settings can be modified in:

```text
conf/base.config
```

## Notes

- The test dataset is intended only for pipeline validation.
- Do not use test results for biological interpretation.
- The paths in `samples.csv` must be adapted to the local environment.
- Reference FASTA and GTF files must correspond to the same genome assembly.
- Docker must be available before execution.
- Use `-resume` when rerunning the same test to avoid repeating completed steps.
- For analysis of full datasets, follow the instructions in the main pipeline README.

For complete information about installation, configuration, Docker environments, parameters, resource management, and full-scale analysis, please refer to the main README of the CattleCell-GTEx single-cell Nextflow pipeline.
